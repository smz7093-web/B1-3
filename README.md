# 자동화 도구 비교 및 구현 과제 README

## 1. 과제 개요
이 과제는 **자동화 도구를 직접 사용하여 실제로 동작하는 워크플로우를 구현**하고,  
도구 간 차이점과 활용 적합성을 비교·분석하는 것을 목표로 합니다.

과제는 아래 **2개의 프로젝트**로 구성됩니다.

- **프로젝트 1: 자동화 도구 비교 구현**
- **프로젝트 2: 자유 주제 자동화 설계 및 구현**

---

## 2. 제출해야 할 산출물

### 프로젝트 1. 자동화 도구 비교 구현
동일한 자동화 워크플로우를 **서로 다른 2개 이상의 자동화 도구**로 구현합니다.

#### 제출물
- 동일한 자동화 워크플로우를 2개 이상의 도구로 구현한 결과
- 각 도구별 **워크플로우 구성 화면 캡처**
- 각 도구별 **실행 결과 화면 캡처**
- **비교 분석 보고서** (`Markdown` 또는 `PDF`)

---

### 프로젝트 2. 자유 주제 자동화 설계 및 구현
반복적으로 수행되는 업무 1개를 정하고, 이를 자동화하는 워크플로우를 설계·구현합니다.

#### 제출물
- 자동화할 **반복 업무 1개 정의**
- 사용할 **자동화 도구 1개 선정**
- **선정 이유 작성**
- **워크플로우 설계 문서**  
  - 설명형 문서 또는
  - 다이어그램 포함 문서
- **구현 화면 캡처**
- **실행 결과 화면 캡처**

---

## 3. 과제 목표
이 과제를 완료한 후, 학습자는 다음 내용을 스스로 설명할 수 있어야 합니다.

- **Trigger**와 **Action**의 개념을 설명할 수 있다.
- **조건 분기(Filter/Router)**의 역할을 설명할 수 있다.
- 서로 다른 자동화 도구의 특징을 비교할 수 있다.
- 특정 업무에 적합한 도구를 선택하고 그 이유를 설명할 수 있다.
- 자동화 흐름을 단계별로 설명할 수 있다.

---

## 4. 기능 요구 사항

## 4-1. 공통 요구 사항
두 프로젝트 모두 아래 조건을 만족해야 합니다.

- **실제로 동작하는 자동화 워크플로우**를 구현해야 한다.
- **Trigger 1개 이상** 포함해야 한다.
- **Action 2개 이상** 포함해야 한다.
- **조건 분기(Filter/Router) 1개 이상** 포함해야 한다.
- 조건 분기 구조가 있는 경우, **각 분기 경로가 실제로 1회 이상 실행된 결과**를 확인할 수 있어야 한다.

---

## 4-2. 프로젝트 1 요구 사항
- 서로 다른 **2개 이상의 자동화 도구**를 사용한다.
- **동일한 워크플로우 구조**로 구현한다.
- 비교 분석 보고서에는 아래 내용을 반드시 포함한다.

### 비교 분석 보고서 필수 항목
1. 사용한 도구 이름
2. 구현 과정 요약
3. **최소 5개 이상의 비교 항목**
   - 예시:
     - UI/UX
     - 설정 난이도
     - 연동 서비스 범위
     - 무료 플랜 범위
     - 실행 로그 확인 방식
4. 각 도구의 장단점 정리
5. 어떤 상황에서 적합한지에 대한 의견 작성

---

## 4-3. 프로젝트 2 요구 사항
- 자동화할 **반복 업무 1개**를 정의한다.
- 사용할 **도구 1개**를 선정하고 선정 이유를 작성한다.
- **자동 실행 구조**를 구현한다.
- **워크플로우 흐름 설명**을 반드시 포함한다.

---

## 5. 보너스 과제 (선택)

### 보너스 1. AI 연동 Action 추가
워크플로우에 생성형 AI를 Action으로 추가하여 텍스트를 자동 생성합니다.

#### 예시
- 요약
- 분류
- 템플릿 메시지 생성

사용 가능한 예:
- ChatGPT
- Claude
- 기타 생성형 AI 서비스

---

### 보너스 2. 실패 알림 및 재시도 전략
워크플로우 실행 중 오류가 발생했을 때 대응할 수 있도록 설계합니다.

#### 포함 가능 항목
- 이메일 또는 메신저로 **실패 알림 전송**
- **재시도(재실행)** 전략
- **대체 경로(Fallback)** 설계  
  - 예: 저장 실패 시 임시 시트에 저장

---

## 6. 제약 사항

## 6-1. 구현 및 동작 제약
- 자동화 도구를 비교 분석하기 위해 **반드시 2개 이상 직접 사용**해야 한다.
- 두 프로젝트 모두 **실제 동작하는 워크플로우**여야 한다.
  - 설계 문서만 제출하는 것은 불가
- 프로젝트 2는 **Trigger 발생 시 자동 실행**되어야 한다.

---

## 6-2. 보안 및 제출물 제약
- 제출물(스크린샷, 문서, 공유 링크)에 아래 민감정보가 노출되지 않도록 해야 한다.
  - API Key
  - Access Token
  - 비밀번호
  - 기타 인증 정보
- 필요 시 **마스킹 처리**한다.
  - 예: `***`
- 계정 이메일 주소도 일부 가려서 제출하는 것을 권장한다.

---

## 6-3. 계정/연동 환경 리스크 완화 가이드
계정 생성과 연동 난이도를 낮추기 위해 아래와 같은 조합을 권장합니다.

### 권장 최소 구성 예시
- Google Sheets + Gmail(또는 Email) + Webhook
- Google Sheets + (Slack 또는 Discord 중 1개) + Webhook

---

## 6-4. 과금 리스크 완화 가이드
- 가능한 한 **무료 플랜으로 완수 가능한 조합**을 우선 고려한다.
- 예시:
  - Make 무료 범위 + Google Sheets
  - 자가 호스팅 가능한 도구 + 무료 연동 앱

### 유료 기능을 사용한 경우
보고서에 아래 내용을 반드시 함께 작성합니다.
- 왜 유료 기능 사용이 **불가피했는지**
- 이를 대체할 수 있는 **무료 대안**

## 9. 한눈에 보는 핵심 요약
- 프로젝트는 **2개** 수행해야 합니다.
- 프로젝트 1은 **같은 워크플로우를 2개 이상의 자동화 도구로 비교 구현**해야 합니다.
- 프로젝트 2는 **반복 업무 1개를 선택해 자동화 설계 및 구현**해야 합니다.
- 두 프로젝트 모두 **실제 동작**해야 하며,  
  **Trigger / Action / 조건 분기**가 포함되어야 합니다.
- 스크린샷, 실행 결과, 분석 문서까지 포함해 제출해야 합니다.
- 민감정보는 반드시 **마스킹 처리**해야 합니다.

## 10. 추천 작성 팁
- 먼저 **가장 간단한 공통 워크플로우**를 정한 뒤 프로젝트 1을 시작하세요.  
  예: `Webhook → 조건 분기 → Google Sheets 저장 + Email/Discord 알림`
- 프로젝트 2는 본인이 자주 하는 반복 업무를 고르면 설명이 훨씬 쉬워집니다.  
  예:
  - 문의 접수 자동 분류
  - 출석/신청 내역 자동 기록
  - 일정 알림 자동 발송
  - 폼 응답 자동 정리
- 비교 분석에서는 단순 기능 나열보다,  
  **“초보자에게 어떤 도구가 더 쉬운가?”**,  
  **“무료 플랜에서 어디까지 가능한가?”** 같은 관점이 좋습니다.
